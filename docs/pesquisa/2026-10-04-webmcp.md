# Pesquisa: vale implementar WebMCP no Evoluto?

> Análise de 04/10/2026. **Decisão: não implementar no MVP. Reavaliar na Fase 2** quando os gatilhos abaixo forem atendidos.

## O que é
WebMCP é uma proposta de padrão (W3C Community Group, editores do Google e da Microsoft) que permite a uma página expor **ferramentas** para agentes de IA que rodam no navegador. Em vez de o agente "clicar em botões" lendo a tela, ele chama uma função com entrada e saída estruturadas ([Chrome — early preview](https://developer.chrome.com/blog/webmcp-epp)).

- **API declarativa:** atributos `toolname` e `tooldescription` num `<form>` existente.
- **API imperativa:** `document.modelContext.registerTool({ name, description, inputSchema, execute, annotations: { readOnlyHint } })` ([guia do Chrome](https://github.com/GoogleChrome/modern-web-guidance-src/blob/main/guides/webmcp/webmcp/guide.md)).
- Exige **contexto seguro** (HTTPS ou localhost).

## Situação em 2026
| Aspecto | Situação |
|---|---|
| Suporte | Chrome: *origin trial* (Chrome 149–156). Edge: atrás de flag. Firefox/Safari: sem compromisso ([Spronta, jul/2026](https://www.spronta.com/blog/state-of-webmcp-july-2026/)) |
| Especificação | Rascunho de Community Group, **fora do caminho de padrão oficial**. A API mudou de `navigator.modelContext` para `document.modelContext` (maio/2026), e `provideContext()` foi removido em março/2026 ([webmcp-checker](https://webmcp-checker.com/blog/navigator-modelcontext-api-reference), [Webfuse](https://www.webfuse.com/webmcp-cheat-sheet)) |
| Quem consome | **Nenhum agente popular chama ferramentas WebMCP ainda.** Claude, ChatGPT Agent, Perplexity e Gemini ainda leem o DOM ou usam capturas de tela. O Gemini no Chrome foi anunciado como o primeiro consumidor ([Spronta](https://www.spronta.com/blog/state-of-webmcp-july-2026/)) |
| Segurança | Riscos: injeção de instruções via descrições de ferramentas e via conteúdo retornado. Recomendações: ferramentas pequenas, `readOnlyHint` em leitura, confirmação humana para ações com consequência ([Chrome — segurança](https://developer.chrome.com/docs/ai/webmcp/secure-tools)) |

## Trade-offs para o Evoluto

| A favor | Contra |
|---|---|
| Catálogo é o caso de uso mais seguro: **só leitura** (buscar produtos, ler análise), sem pagamento nem dados pessoais | **Ninguém usaria hoje:** sem agente consumidor, o ganho real é zero |
| Reaproveitaria `filtrar()` e `carregarDetalhe()`, com pouco código | **API instável:** já houve renomeação e remoção de métodos em 2026. Código escrito agora tende a quebrar |
| Diferencial futuro para compras assistidas por agente (Fase 2) | **Não vale nota:** o PDF não pede, e o professor precisaria de flag ou *origin trial* para testar |
| | **A API declarativa quebra a validação HTML:** `toolname`/`tooldescription` não são atributos válidos, o que pesa contra o critério "HTML" quando o professor usar o validador W3C |
| | **Prazo:** entrega em 05/10. Qualquer escopo extra compete com os 10 pontos |
| | Mais um conceito para o aluno explicar na correção, sem retorno de nota |
| | Incerteza para afiliados: não se sabe se agentes vão preservar os links rastreados (atribuição de comissão) |

## Veredito
Os contras dominam no MVP: custo de prazo e risco de validação, com benefício nulo hoje. **Não há plano de implementação nesta fase**, conforme o critério combinado ("só planejar se os trade-offs mostrarem vantagem").

## Gatilhos para reavaliar na Fase 2
1. WebMCP disponível no **Chrome estável** sem flag nem *origin trial*.
2. Pelo menos **um agente popular** (ex.: Gemini no Chrome) chamando ferramentas WebMCP de verdade.
3. API estável por 6 meses ou mais (sem renomeações).
4. Clareza sobre **atribuição de links de afiliado** em compras feitas por agentes.

O desenho atual já facilita a adoção futura: a lógica de busca e de detalhes fica em funções puras e testadas (`js/estado.js`, `js/api.js`), que poderiam ser expostas como ferramentas somente leitura sem refatoração.
